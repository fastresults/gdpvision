# src/lib rules

- **Narrative retention**: daily `purge_stale_signals` purges unmarked signals >30d; signal queries share that filter.
- **Partner data (GDP Advisor)**: companion sites read through `src/lib/public-data/partner.server.ts` (v2 API under `/api/public/v2`, partner keys `gdpp_…`, admin at `/admin/partner-keys`), which delegates to v1 resource handlers via `readPublicResource` so one set of public/approved filters governs every external read.
- **Caribbean Indices**: CGX/CHX/CGV/CCX + Sextant. Method layer in `index_specs`/`index_pillars`/`index_indicators` (migrations only); values come from `src/lib/indices/sources.server.ts` (WDI, IMF WEO, public non-inferred KPIs, verified `index_evidence`) and every number is decided by pure `indices/scoring.ts` — never by AI. Runs freeze inputs in `index_inputs`. Only a published, signed-off edition leaves GDPVision (`public-data/indices.server.ts`); trackers stay private. PRD: `docs/prd/PRD-caribbean-indices.md`.
- **Media scan**: shared regional/international outlets feed under pseudo-country `CAR` and fan out to each country the classifier names (`intake_items.countries`); media-only places live in `narrative_media_countries`, not `countries`, so other chambers never see them. Priority score (`narrative-priority-score.ts`) orders within P-levels only, keeping SQL priority counts in step.
- **Business case**: keep claims and source links in `src/lib/business-case.ts`; separate capabilities, pilot tests and contract terms to avoid implying proven results.
- **Events → Second Brain**: Events Admin is the source of truth; `events/brain-sync.server.ts` (pure rules in `brain-sync-rules.ts`) mirrors published, non-archived editions with their speakers/partners into `memory_objects`, hides (never deletes) records for drafts/archived/removed items, and never sends registrations — so the brain matches what visitors can see.
- **GDP Events partner feed**: companion GDP Events site reads `/api/public/v2/events*` (shaping in `public-data/events-feed.ts`, handlers in `partner.server.ts`); partner-only permissions live in `public-data/partner-scopes.ts` (not `API_SCOPES`, which keys v1 per-country resources). Only published, non-archived editions leave; partner registrations go through `register_for_event` and are tagged `event_registrations.source = partner:<key id>`.
