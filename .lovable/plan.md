## Problem
Once a stage commits, its draft is deleted from `onboarding_drafts` (the status query filters `committed_at IS NULL`). The accordion body then falls through to the "No draft yet. Click Run AI research…" message — even though the stage is committed. There's no human-readable summary of what was actually saved.

## Goal
When an admin opens any of the 11 stage accordions on `/admin/countries/:code/onboard`, show a short, elegantly written **executive summary** of the committed data for that stage (2–5 sentences + a few key facts), instead of the misleading "No draft yet" text. Keep the raw draft editor for the pre-commit review state; the summary is the committed-state view.

## Approach
Store one executive summary per (country, stage) in a new table, generated by Lovable AI from the committed payload. Render it inside the accordion body. Backfill on demand for already-committed stages.

### 1. Data — new table `onboarding_summaries`
Migration (with the standard GRANT + RLS block):
- `country_code text`, `stage text`, `summary_md text`, `highlights jsonb` (array of `{label, value}`), `model text`, `generated_at timestamptz`, `source_run_id uuid null`, primary key `(country_code, stage)`.
- RLS: readable/writable by admins only (reuse `has_role(auth.uid(), 'super_admin')` pattern already used elsewhere).

### 2. Server — summary generation
New file `src/lib/country-onboarding/summaries.functions.ts`:
- `generateStageSummary({ countryCode, stage })` — admin-gated server fn.
  1. Reads the committed source of truth for that stage from its target table (`countries`, `country_sectors`, `ministries`, `ministry_sectors`, `country_sources`, `country_kpis`, `sector_dossiers`, `ministry_profiles`, `country_source_chunks`, `memory_objects`) plus the country row for context.
  2. Calls Lovable AI (`openai/gpt-5.5`, via `createLovableAiGatewayProvider`) with a stage-specific system prompt: "You are a cabinet-grade briefing writer. Produce a 2–4 sentence executive summary in confident, plain English, plus 3–6 key highlights." Uses `Output.object({ summary_md, highlights: [{label, value}] })` (no `.min/.max` — clamp in code).
  3. Upserts into `onboarding_summaries`.
- `getStageSummary({ countryCode, stage })` — returns the row or `null`.
- Hook summary generation into each existing `commit*` function so a fresh commit auto-refreshes its summary (fire-and-forget with try/catch; commit still succeeds if summary fails).

### 3. Status query
Extend `getOnboardingStatus` to also return `summaries: OnboardingSummary[]` for the country (single extra select). No breaking change.

### 4. UI — accordion body
In `src/routes/_authenticated/admin/countries.$code.onboard.tsx` `StageCard`:
- Compute `committed = lastRun?.status === "committed"` and `summary = summaries.find(s => s.stage === stage.key)`.
- When `committed`, render an **Executive Summary** block at the top of the accordion body:
  - Small "Executive summary" eyebrow label.
  - `summary_md` rendered with the existing markdown renderer (or a minimal prose block using Tailwind `prose-sm`).
  - Highlights as a 2-column key/value grid (label in `text-ink-500`, value in `font-medium tabular-nums` when numeric).
  - Footer meta: `Generated {relative time} · model {summary.model}` and a subtle "Regenerate" text button that calls `generateStageSummary` and refreshes.
- If `committed` but no summary row exists yet (backfill case), show a one-line "No summary yet" + "Generate executive summary" button that calls `generateStageSummary`.
- Replace the current "No draft yet…" message so it only shows when the stage is **neither** committed nor has a draft (true empty state).
- Keep the existing draft JSON editor + citations + Commit button exactly as-is for the review state.

### 5. Copywriting per stage
Per-stage system prompts baked into `summaries.functions.ts` so voice stays consistent:
- 1 Profile — country identity in one paragraph; highlights: currency, fiscal year, population, HDI, head of government.
- 2 GDP — nominal USD with WB/IMF cross-check note; highlights: latest GDP, year, YoY %, per-capita.
- 3 Sectors — where output is concentrated; highlights: top 3 sectors by share.
- 4 Ministries — shape of cabinet; highlights: ministry count, notable portfolios.
- 5 Ministry×Sector — how portfolios map to the economy; highlights: densest ministries.
- 6 Sources — evidence base; highlights: counts by tier (gov/regional/multilateral/media).
- 7 KPIs — macro/fiscal/social pulse; highlights: 3–5 headline KPIs with latest values.
- 8 Sector dossiers — narrative posture per sector; highlights: dossier count, benchmarked peers.
- 9 Ministry deep-dive — minister-level readiness; highlights: profiled ministers, flagship programmes.
- 10 Corpus ingest — retrieval readiness; highlights: chunks embedded, sources covered.
- 11 Second-brain seed — cabinet-ready memory; highlights: positions, audiences, outlets, facts, risks counts.

## Out of scope
- Changing agents, commit logic, target-table schemas, or the draft/review flow.
- Public-facing rendering — summaries are admin-only.
- Regenerating summaries for every country in bulk (per-stage "Regenerate" button covers it; "Run all pending" continues to only run agents).
